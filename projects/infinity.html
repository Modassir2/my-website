Why it exists

Jarvis was the first thing I actually wanted to build. Not a chatbot with a nice coat of paint, but something that could look at the screen, open the right file, search the web, and keep track of what happened.

Infinity is that idea, rebuilt enough times that it now works. It runs in the terminal because that is where I already am. It can switch tools at runtime because carrying every capability in context is a waste of tokens and attention.

Infinity is a desktop-first AI assistant that runs in the terminal and can switch tool sets dynamically based on the task.

What it does

01

Runs local or cloud models

Point config.json at llama.cpp, Ollama, LM Studio, vLLM, or any hosted OpenAI-compatible endpoint.

02

Sees the desktop

Captures screenshots for visual context, with multi-monitor support through primary_monitor.

03

Changes its tool set

A get_tools call swaps the active tools at runtime instead of loading everything at once.

04

Uses the web

Searches through a self-hosted SearXNG instance, with Wikipedia as a fallback when search is not configured.

05

Reads real files

Plain text, CSV, JSON, PDF, DOCX, and images. The boring formats are usually the ones that matter.

06

Remembers

Persistent chat history and memory consolidation between sessions, so the assistant is not starting cold every time.

How it works

  1. Start an endpoint.

    Run a local server or use a hosted one. The config holds the base URL, model ID, context length, and the monitor Infinity is allowed to use.

  2. Compose a tool set.

    Infinity decides which tools the task needs. get_tools swaps the set at runtime rather than keeping every tool in the prompt.

  3. Compress the context.

    Screenshots, file contents, and search results are trimmed to a configurable character limit before they reach the model.

  4. Keep the thread.

    Conversation history and memory live on disk. /clear clears the conversation; /update reloads config and memory.

What the README says

These are the capabilities listed in the repository, in the README's own words:

  • Local or cloud OpenAI-compatible model support
  • Desktop screenshot capture and visual context
  • Multi-monitor support via primary_monitor
  • Tool-set switching at runtime with get_tools
  • Web search using a configured SearXNG instance
  • Wikipedia lookup support
  • File and directory management tools
  • Reading support for plain text, CSV, JSON, PDF, DOCX, and images
  • Persistent chat history and memory consolidation
  • Rich terminal UI with markdown formatting
