Why it exists

I had folders full of screenshots, receipts, documents, and memes that I kept meaning to sort. Doing it by hand was boring. Sending them to a cloud API was not the point.

The useful version of this tool is local, copies instead of moves, and lets me define the categories. It does not decide that my life should be organised into someone else's taxonomy.

Point it at a folder full of images. A vision model reads each one and files it into the categories you define — live progress and all.

What it does

01

Stays local

With a local server, no image or prompt leaves the machine. Nothing is uploaded or logged by a third party.

02

Copies, never moves

Originals stay exactly where they are. Sorted files land in output/<category>/.

03

Your categories

One JSON file for the category list, one Markdown file for the prompt. Nothing is hardcoded.

04

No silent failures

Warnings and errors go to a JSON-lines log that can actually be parsed.

05

Resumable

Interrupted a 5,000-image run? Restart and pick up where it stopped.

06

Handles flaky setups

Unplug the external drive or drop the server mid-run, and it waits and retries instead of dying.

How it works

image folder→ base64 data URL→ vision model→ sort_image tool call→ enum validation→ output/<category>/
  1. Walk the folder.

    Recursively counts .jpg, .jpeg, and .png files, then works through them with live directory and total progress.

  2. Send the image and the instructions.

    Each image is base64-encoded and sent to an OpenAI-compatible vision endpoint with the category prompt.

  3. Force a tool call.

    The model must answer through a single sort_image call. The category argument is an enum built from categories.json, so anything outside the list is rejected and retried.

  4. Verify, copy, log.

    The returned category is checked against the list, the file is copied into the matching output folder, and the run moves on. Failures after three bad requests are skipped and logged.

Requirements, honestly

RequirementDetail
Python3.9+ (developed and tested on 3.13.3)
Modelqwen3.5:2b recommended; any vision-capable model with function calling works
ServerAn OpenAI-compatible endpoint, local or cloud
Tool callingNot optional. The classifier only reads the sort_image tool call.
Why the 2B model: it is small enough to run on a laptop CPU, good at reading printed and handwritten document text, and supports tool calling without extra setup. Bigger vision models help on dense or low-quality scans.

What the README says

  • Local-first: no image or prompt leaves the machine when using a local server
  • Copy, never move: originals stay where they are
  • Bring your own categories through a JSON file and a Markdown prompt
  • Warnings and errors go to a JSON-lines log
  • Resumable after an interruption
  • Waits and retries when a drive or server drops mid-run
